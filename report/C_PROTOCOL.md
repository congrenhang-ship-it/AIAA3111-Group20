# C 验证方案与冻结规则

负责人 C。制定于 2026-11-11，接入 A 的 `Task_A` 提交 `26c1c32` 后、首次真实 C 验证评价前记录。本方案不声称 B5 或全组 G2 已完成。

1. 原始数据必须匹配 A 的 SHA-256；直接调用 `load_data`、`split_data`。仅训练/验证参与本次开发，测试部分不打分、不比较算法。
2. 沿用原先实现：30 个输入特征，训练段 StandardScaler；K-means 候选 k=3/5/8，seed=42/43，各 n_init=10；同一固定训练子样本最多 1,000 笔。按平均有效 silhouette 最大选 k，并列选小 k；ARI 只做稳定性诊断。最终拟合 seed=42。
3. Isolation Forest 固定 100 棵树、max_samples=256、contamination=auto、seed=42、n_jobs=1，不另跑大规模调参。所有模型均在含正常与欺诈的混合训练特征上拟合，不读取训练标签筛选样本。数值库线程限制为 1，并记录环境版本。
4. 预算 0.1%、0.5%、1%、2%。主要选择预算预定为 1%；K=ceil(Nq)，按风险降序/row_id 升序。报告 AP 和所有预算，不根据验证结果改变主要预算。阈值不是容量，主实验不使用固定分数阈值替代 top-K。
5. 需要一个异常方法参与后续分类组合时，按验证集 1% 预算下 TP 最大选；并列按 AP 最大，再按方法名排序。该选择使用验证标签，必须披露。
6. 分类预测到位后，在同一验证集对 α=0/25/50/75/100% 的分类配额做固定 K 去重补齐。按 1% 预算下 TP 最大选；并列优先更大的分类配额。保留 α=100% 的纯分类基线，不为了展示组合而强行选混合。B5 未到位时不生成正式分类组合结论。
7. 两种异常方法之间的名单对照仅用于诊断；图示 50/50 配额不视作选定分类组合，不把并集容量接近 2K 的检出数当成同预算收益。
8. 训练管线保存到本地 `c_models.joblib`，保留训练段拟合结果，不在 train+validation 上重拟合。向 A 交付聚类数、异常配置、特征/顺序、版本、划分指纹、预算和排名规则。C 的冻结文件始终区分无监督部分、待 B5 的组合部分及全组 G2。
9. 群体画像使用标签作事后描述；同时报告组内预算和全局 top-K 在各组分布。空组/无正类按 N/A。调用 A 的一小时窗口接口作为验证诊断；最终时间窗口仍由 A 在 G2 确定。
10. 公开交付仅包含汇总、聚合特征均值和图；完整预测、行 ID、模型、错误案例保留在 Git 忽略的 data/。所有结果附代码与输入文件哈希。最终测试由 A 在全组方案冻结后统一开展。

如果发现实现错误，应记录修复与重跑原因，不能静默把验证选优规则改成更有利的版本。本次未规定的额外模型、第二数据集或 LLM 不纳入 C 范围。
