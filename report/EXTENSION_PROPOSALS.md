## E01 金额覆盖与分组

研究问题：检出笔数较高的方法，是否也覆盖较多欺诈交易金额？

- 欺诈金额覆盖率 = 被审核欺诈的原始 Amount 总和 / 该数据段全部欺诈的原始 Amount 总和。
- 对主分类器、固定 IF、簇距离、冻结组合和 E06 参考排序使用相同预算。
- 同时保留笔数 Recall、TP/FP、审核数，检查少数大额交易是否主导金额指标。
- 金额组边界仅由训练段原始 Amount 的 50%、90%、99% 分位数确定，重复边界合并，外侧开放；记录精确边界。组内报告样本/欺诈数、金额及全局审核名单在各组的覆盖，不重新分配独立组预算。
- 欺诈金额分母为零时记 N/A。这里只能称金额覆盖，不能称实际挽回损失；数据没有追回金额。

验收：原始金额按 row_id 对齐，组计数及金额加总一致，独立小样例可手工核算；一张数量/金额对照图及汇总足够。

## E02 配对区间与方法差值

研究问题：少量欺诈样本下，固定方法的差距是否稳定？

默认协议：seed=42，500 轮配对逐行 bootstrap，给出 AP、Recall@1% 及方法差值的 2.5%/97.5% 经验分位区间。主要比较分类–IF，以及冻结组合–分类；簇距离提供单方法区间。各方法每轮使用同一抽样索引，重新计算该轮预算排名。

补充 200 轮非重叠 1800 秒时间块的配对重采样作为敏感性检查，共同起点为 0。抽取与观测时间跨度内块槽数相同的块（含空槽），保留块内全部交易，使用该轮实际 N 重新算 K，记录块数量和首尾不完整块。它不构成长期漂移检验。

- 有放回抽样会重复源 row_id，必须保留抽样实例身份，统一按 score、源 row_id、实例顺序处理并列；不能直接把重复 ID 传给要求唯一 ID 的公共接口。
- 无正类样本的 AP/Recall 为 N/A，报告有效轮数和跳过原因；不可偷偷重抽到每轮都有欺诈。零有效轮或退化分布须明确标注，不能制造显著性。
- 保留样本配对，不单独为两个模型抽样；不重新训练，也不重新选组合。
- 区间描述已选固定模型在所用重采样假设下的不确定性，不覆盖全部训练/选参不确定性；不把区间重叠与否直接当作正式显著性检验。

验收：相同预测的差值为零；重复运行一致；反向差值符号一致；稀有正类、重复实例和空块处理有必要检查。输出主区间与块敏感性对照。[SciPy bootstrap 文档](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.bootstrap.html) 提供配对抽样机制，时间块抽样需另行实现。

## E03 标签不足学习曲线

研究问题：减少可见训练标签时，分类与异常检测的相对表现怎样变化？

- 标注比例固定为 5%、10%、25%、50%、100%；种子 42/43/44，用分层抽样控制标签比例。每个种子构造按类固定随机排列的嵌套子集；记录实际笔数/欺诈数及掩码 SHA-256。分层抽样依赖真实标签，仅是受控模拟，不代表实际标注流程。
- 代表分类器使用 B 的带类别权重逻辑回归，固定配置，在每个已标注子集上拟合完整管线（包括缩放）；100% 若结果相同可复用，需记录。
- IF 参考使用原先固定基线：原始 30 特征、训练段 StandardScaler、100 棵、max_samples=256、contamination=auto、seed=42、n_jobs=1；在完整无标签训练特征上拟合一次。此参考不采用经完整标签选择出的改进配置，不新调参。
- 隐藏标签不改成正常；训练和拟合范围明确写出。分类管线看到较少训练记录，IF 看到全部无标签特征，这是“少标签但未标注交易可用”的条件比较，不能解释为仅算法不同。
- 在同一验证段比较 AP、Recall@1%、Precision@1% 和时间；画均值及三种子范围，不能把三次范围称为 95% 置信区间。
- A7 记录全部比例、种子、配置和模型/重建方式。A8 在测试段评价所有事前规定条件，不只挑验证或测试最好的比例。主实验原模型与组合不因此重新选优。

B 可直接调用 C 已有 IF 与公共评价接口，独立完成整项实验；C 不另建第二套标签模拟。验收需检查隐藏标签不进入拟合、掩码只涉及训练段、同种子可复现。无论有无性能交叉都保留结果。

## E04 规则重叠与增量覆盖

沿用 D 已验证的固定候选集合，不重新扩大特征、分箱或规则搜索。

- 计算规则覆盖交易的 Jaccard 矩阵；零并集记 N/A，注明计算的数据段。
- 规则顺序按训练 lift 降序、confidence 降序、前件长度升序、规则 ID 升序固定，在 G2 前记录。绘制每增加一条规则后去重的累计交易数及欺诈数，同时显示增量。
- 标记完全重复覆盖、前件包含和高重叠现象，报告全部规则；精简展示集仅在验证阶段确定，不改变原固定规则测试集合。
- 将覆盖与分类/IF 的固定 top-K 误报、漏报联系，选择有明确来源的案例。不同规则的欺诈数不能直接相加。

这是解释性覆盖分析，不自动形成 exactly-K 排序检测器。不能将覆盖几千笔的规则与审核几百笔的模型直接宣称优劣。验收：累计并集单调、交并集计数正确、零计数处理明确，提供热图、曲线及案例。

D 执行细则（2026-11-14，验证运行前记录）：高重叠标记阈值为 Jaccard>=0.9；展示集取固定训练顺序中前五条有新增验证欺诈覆盖的规则，原 21 条待测试集合不变。错误案例按 classifier_FN、classifier_FP、IF_FN、IF_FP 顺序，各取被规则覆盖的源 row_id 最小的两例，跳过前面已列案例。其他成员的逐行预测不在 Git 中时，只用已有公共接口重建已冻结的带权 LR 与改进 IF（100 棵、max_samples=4096、seed=42），不重新搜索候选或配额；核对原验证主预算 TP=49/24 后再输出关联。逐行预测留本地，共享 JSON 仅保留汇总及少量可追溯案例。

## E05 重要性与错误分析

对 B 已选带权逻辑回归管线，使用 AP 为评分，完整验证段、seed=42、每个原始输入特征重复置换 5 次；记录均值及标准差，显示前 10 项但保留全部数值。不据重要性再删特征或选模型。A7 固定协议，A8 后可按同一协议补测试解释。

特征每次由原表复制后单列打乱，训练管线不重新拟合。将已有误报/漏报案例与重要特征的数值差异连接，案例规则固定为审核线附近的误报、漏报及高排名误报，不挑选支持预设故事的样本。

V 特征保持匿名命名，不虚构消费行为。重要性是模型依赖，不是因果解释；特征相关性也会影响结果。[scikit-learn 说明](https://scikit-learn.org/stable/modules/permutation_importance.html)

## E06 简单参考与预算提升倍数

保留公共评价已提供的随机审核期望，不重复做随机搜索。增加一个不训练的 Amount 降序参考（并列 row_id 升序），不看结果后换成升序。

- 所有参考采用同一数据段和 K，报告 AP（有排序者）、TP、FP、Recall、Precision 及金额覆盖。
- 预算提升倍数 = Precision@K / 数据段欺诈比例；无欺诈时记 N/A。随机期望 TP=K×欺诈比例，允许非整数，不能当实测计数。
- 金额排序本身倾向大额覆盖，E01 的金额优势应结合笔数指标解释。

验收：参考输出与主方法使用同一公共评价；期望和实测分列；不把恒定分数按 row_id 排序误当随机抽样。

## E07 假设成本敏感性

复用原四档预算，定义假设损失 L = c_FP×FP + c_FN×FN。固定 c_FP=1，c_FN=10/50/100，输出各预算的损失、漏报数及误报数。无需再训练模型，也不把 score 当已校准的欺诈概率。

这些系数是假设的相对成本，不能写成真实货币收益，也不等同于 E01 的金额覆盖。主要研究预算和错误类型之间的取舍。若展示“成本最低预算”，只能在验证阶段按事前规则确定、在 G2 记录后用于测试；最终测试表保留全部预定场景，不事后挑最有利成本比。

验收：可手工核算的小样例；成本比与预算完整记录；一张紧凑对照图/表即可。

## E08 固定阈值跨时间迁移

现有 top-K 是固定容量政策。新增固定阈值政策，检查其后续审核量是否稳定。

- 仅对主分类器和固定改进 IF，在验证段各取主预算 K 对应的第 K 高分作为阈值 t；记录数值、方法、精确拟合版本、验证指纹及 ties。
- 应用 score>=t，不承诺恰好 K；并列分数可能使验证审核数也超过 K。明确报告目标预算与实际审核率。
- A7 冻结阈值，A8 在测试及已约定时间窗口原样应用，输出实际审核数/率、TP/FP、Recall/Precision，另列 top-K 结果。
- 不逐窗重选阈值，不把窗口 top-K 的独立容量与全局 top-K 或固定阈值容量混为一谈；无正类窗口仍标 N/A。

验收：等于阈值、全部低于阈值、无正类和空窗口处理正确；阈值不读取测试分数后再决定。该诊断只支持两天内的短期观察，不宣称长期漂移或生产部署效果。[时间验证背景](https://fraud-detection-handbook.github.io/fraud-detection-handbook/Chapter_5_ModelValidationAndSelection/ValidationStrategies.html)

### E09 数据来源、规模与接口

采用 [Handbook 公开生成方法](https://fraud-detection-handbook.github.io/fraud-detection-handbook/Chapter_3_GettingStarted/SimulatedDataset.html)。采用 60 天、seed=42、5000 客户、10000 终端。A 已完成 1 天的资源和字段试运行，在建模前固定生产规模、生成机制参数、来源版本、许可和依赖。两次生成的指纹见 [A-N1 验收](../results/tables/handbook_a.json)。若资源不适用，必须在模型结果出现前调整并记录，不能按检测效果选择生成设置。

正式默认按天切分：前 30 天训练、接着 15 天验证、最后 15 天测试，同时间不跨边界。保留稳定整数 row_id、Class、原始 Amount、相对秒 Time；实体和生成机制信息作为单独元数据。记录文件 SHA、数量、比例、时间范围、各段指纹及自然类别比例，不平衡处理只作用训练。

为新数据提供 dataset_config/feature_columns，不替换 ULB 全局 FEATURE_COLUMNS，不拼两套数据表。原预测表必需列不变，dataset_id 放在模型/运行配置、汇总和命名中，避免跨数据集 ID 混用。客户/终端 ID、TX_FRAUD_SCENARIO、真实标签、标签到达时间不作为数值特征；机制类型只用于事后诊断。

A-N1 统一元数据保留原 CUSTOMER_ID/TERMINAL_ID（不入模），视图键固定为 transaction_only、customer_history、terminal_history、both_history，E12 追加 both_history_graph。字段映射与各视图列名在 manifest 中固定；A 一次交付后 B/C 不各自重算另一套历史。

单笔视图用金额与模拟交易时段 sin/cos；不直接把客户/终端编号当连续数。历史接口输出过去 1 天、7 天的客户/终端交易次数和平均金额，以及当前金额相对过去客户均值；首次交易给 0 并带历史缺失指示，历史均值非正时比例置 0 并标记，避免除零。所有统计只用 Time<t，同时间批次全部预测完再入状态。标准化/编码/插补的可学习参数只 fit 该情景声明的拟合记录。

验收包括小型手算时序、未来添加极端交易不改变已有特征、同时间互不可见、训练/验证边界、标签/机制字段排除、可重建指纹。数据生成和加载由 handbook.py 提供，历史实现位于 temporal.py，回归检查位于既有 tests/test_task_a.py。缓存留在被忽略的 data/handbook/。

### E10 四组历史消融

报告 AP、0.1/0.5/1/2% 预算计数、金额覆盖与运行时间。主预算仍为 1%；先保留全部条件，不按测试选最佳特征视图。分类与异常的各自训练接口消费同一 numeric feature view，模型权重重新在 Handbook 训练，不能直接拿 ULB 的已训练模型迁移。

两类历史为后续统一参考视图，不看消融结果后换成最有利的一组。[历史特征参考](https://fraud-detection-handbook.github.io/fraud-detection-handbook/Chapter_3_GettingStarted/BaselineFeatureTransformation.html)

### E11 开发期滚动和标签延迟

采用预定的最近 30 天标签窗口、每 7 天更新，以 LR 为主。开发期比较静态基线和周更新，再固定周更新下模拟标签统一延迟 0、1、7 天；IF 无标签静态参考不因标签延迟额外改变训练条件。

在开发决策时刻 t，只允许标签 Time+delay<t 的记录；拟合区间为 [max(数据开始,t-delay-30天),t-delay)。特征查询仍只用当时已出现的无标签交易。记录每次拟合的截止时刻、实际数量、欺诈数、缩放范围与更新次数。

本轮滚动仅在训练/验证开发期进行。最终测试开始前，按预定时间规则为每个情景拟合并保存最后可用模型快照（可能使用当时已可得的开发验证标签，必须声明）；不按 AP 挑快照。实现以训练切点第 30 天为周更新起点，更新日为 30、37、44。最后一个验证日 [44,45) 对各条件均为未用于拟合的校准段，用来为各自保存的模型确定 1% 阈值。G2 冻结参数、允许拟合范围、文件哈希和阈值后，测试期模型不更新，测试标签不回填。ULB 的原训练/测试政策完全不变。

输出分期表现及延迟曲线，明确延迟、样本量与新近数据的影响；不声称实际标签都统一延迟同样天数。真正测试期在线更新不进入当前任务。[验证策略参考](https://fraud-detection-handbook.github.io/fraud-detection-handbook/Chapter_5_ModelValidationAndSelection/ValidationStrategies.html)

### E12 基础关系图特征

客户和终端是二分图节点，过去交易为边。只增加过去 7 天客户的不同终端数、终端的不同客户数、当前客户–终端对过去是否出现过三个关系量。E09 的基础历史保持次数/金额，不提前把同一关系量算进基线，避免重复计算所谓增益。

C 实现关系状态和单次增量消融：两类历史 vs 两类历史+关系量，LR/IF 复用固定管线。更新遵守严格过去和同时间批次规则，提供小图核算。原始 ID 不直接入模。无需 GNN、图嵌入或复杂社区算法，关系图可视化只选小型匿名样例，不展示全图制造复杂感。

### E13 冷启动分群

基于初始训练段出现过的客户集/终端集，固定四个互斥群体：两者已见；仅新客户；仅新终端；两者均新。只分析 E10 静态模型，避免把后续更新后已见实体仍叫实时冷启动。

报告交易数、欺诈数、历史可用率、AP 及一个全局 top-K 在各组的审核/检出分配；不要给每个群体另配 K 后再相加。无欺诈记 N/A，罕见群体注明证据不足；不强制重新生成数据来凑群体差异。这是实体新颖性分析，不是人口公平性结论。

### E14 历史缺失压力测试

固定使用 E10 两类历史视图的已训练模型，不重新调参。模拟评分时历史日志保留不全：缺失率 0/10/30%，种子 42/43/44，以源 row_id/固定种子决定历史记录是否进入查询状态，不使用标签或分数决定删除。

当前被评价交易及其标签不删，训练模型仍用完整训练历史；仅验证/测试评分时重建可见历史（包括较早训练记录中的随机不可见项），并用缺失指示处理无历史情况。特征查询严格过去，当前交易若保留也只能在评分后加入，未来记录不能影响当前值。

输出 AP/Recall@1%/金额覆盖随缺失率的变化，记录实际可用率和三种子范围，不称 95% 区间。不将掩码重复样本当新数据。所有比例/种子在该数据集 G2 中预定，测试阶段不另选“最稳”的掩码。

### E15 语义规则与生成机制诊断

D 复用原短规则方法，新增字段固定为当前金额、客户相对金额、客户/终端过去 7 天次数；最多两项前件、三箱，对比原等宽/等频与覆盖门槛，保持有限搜索。训练确定分箱和规则，验证覆盖/稳定性；报告重叠与同预算模型错误关联。

按生成器提供的机制标签作事后分群：报告各机制样本量、模型召回和规则覆盖；若原数据允许机制重叠，分别注明，不直接加总。机制标签不参与输入、筛选测试样本或选择最佳规则。解释哪些发现由人工生成机制预设、哪些未改善，不能把模拟关联当真实金融因果规律。
